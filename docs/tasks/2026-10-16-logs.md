# Task: log retention and phone logs on the PC (role `logs`)

Branch `antigravity/logs-2026-10-16` from `origin/integrate/v3.1`. Draft PR into `ccr-65b98b7a-8b3t20`,
title `[antigravity] logs`. Follow `AGENTS.md` (all hard rules apply).

## Owner's decisions (do not change them)
1. **No log is ever deleted automatically**, on the PC or on the phone. Only the owner deletes them.
2. **Windows: a "Clear logs" button** deletes the PC's log files (its own and the saved phone logs),
   after a Yes/No confirmation. Nothing else deletes them.
3. **Phone logs are saved on the PC** as files, next to the PC's own logs.
4. **On the phone, only connection-failure logs are stored in a file**, and that file is **never
   deleted** (no rotation that deletes, no retention, no button on the phone).

## What exists today (read the code first)
- Windows `windows/src/FileLogger.cs`: daily files `%LOCALAPPDATA%\PdaNext\logs\pdanext-YYYYMMDD[.N].log`,
  2 MB parts, and `CleanOldLogs` deletes files older than 7 days (hourly). `Diagnostics.cs` zips logs.
- Phone `core/.../LogSystem.kt`: `LogRingBuffer` (memory, 2000 entries, redacted) served at `GET /log`
  (loopback only); `RotatingFileLogger` writes **every** line and deletes old parts (maxFiles = 2),
  wired in `android/.../RelayService.kt`.

## Do
- **PC:** remove `CleanOldLogs` and the retention (keep 2 MB parts, never delete). Add a
  "Clear logs" button in the log row of `MainForm` (beside "Save diagnostics"); confirm, then delete
  all `*.log` in the logs folder (skip files that are in use, report how many were deleted).
- **Phone -> PC:** give each `LogEntry` a monotonic sequence number and support `GET /log?since=<seq>`
  (only entries after `seq`; keep `GET /log` without `since` exactly as today, same text format).
  Return the last sequence number in a response header `X-Log-Seq: <n>`. The PC polls every 30 s
  while connected and once right before disconnecting, and appends new lines to
  `phone-YYYYMMDD.log` in the same folder (UTF-8, redacted again with `SecretRedactor`). If the phone
  restarted (sequence went backwards), start again from 0.
- **Phone failure file:** replace the every-line `RotatingFileLogger` with a failure log that keeps
  only connection failures: TCP connect failures, UDP flow failures, DNS failures, router link
  errors (link dropped with an exception, keep-alive/write failure), relay start/accept errors, and
  later tunnel (Xray) connect failures. Use `LogLevel.WARN`/`ERROR` with a source, so the filter is
  `level >= WARN`, not string matching. File `files/logs/failures.log`, append-only, never deleted;
  when it passes 5 MB start `failures-2.log`, `failures-3.log`, ... (never delete one). Serve the
  file content at `GET /log/failures` (loopback only) and have the PC save it as
  `phone-failures.log` (overwrite the PC copy each time; the phone keeps the original).
- `Diagnostics` includes the saved phone logs and `phone-failures.log`.
- Tests: Kotlin (`core/src/test`): sequence + `since`, failure filter, no deletion past 5 MB.
  Windows (`windows/tests`): no deletion by `FileLogger`, the `since`/restart logic of the poller
  (make it a pure function you can test), Clear logs deletes only `*.log` in the given folder.
